# 离线评估方法说明

`evaluate` 只回答一个问题：**某个候选澄清策略相对当前日志策略，是否值得进入小流量实验**。
它不代替用户执行任何动作，也不产生上线操作。所有结论都基于历史记录中可识别的部分。

## 1. 估计量（estimand）随输入模式声明

输入文件的 `mode` 决定估计单元，两种模式识别的东西不同，不能混用：

- `single_step`：估计单元是一次决策。识别的是“在日志策略产生的上下文分布下，
  单步决策规则变化带来的期望单步结算收益”。它**不包含**该决策对后续状态、后续
  决策的影响。同一请求有多次决策时该模式直接报错，不允许把多步请求拆成互不相关
  的曝光。
- `trajectory`：估计单元是一整段请求轨迹。识别的是“整段策略变化的期望整段结算
  总收益”。轨迹的重要性权重是逐步似然比的连乘
  `∏_t π_e(a_t|s_t) / π_b(a_t|s_t)`，配的是整段最终收益。

多步模式**禁止**用“单步概率乘一个最终收益”冒充轨迹价值：那不是任何合法的估计量，
会随步数系统性偏差。模拟演示三用已知生成机制展示了这一点（扁平化估计偏差约 -0.46，
联合似然比的 SNIPW 偏差约 -0.02）。多步模式因此不构造单步收益模型，只提供重权重估计。

## 2. 可核验基准与估计器

**基准（factual baseline）**：日志策略的事实均值，只在 `reward_known_at ≤ cutoff`
的已结算单元上求平均。可以直接对记录求和复核，输出的 `baseline.check` 标明这一点。

单步模式同时给出四类估计，便于互相印证：

| 估计器 | 做法 | 取舍 |
| --- | --- | --- |
| IPW | `mean(w·y)`，无截断 | 无偏但方差大，对小概率动作极敏感 |
| SNIPW | 自归一化 `mean(w·y)/mean(w)` | 降方差、对权重总量更稳，但引入小样本偏差 |
| 截断 SNIPW | 权重截断到 5/10/20/50 四档 | 牺牲无偏性换稳定；逐档展示并报告触顶比例，暴露对极端权重的敏感程度 |
| DM / 双重稳健 DR | 上下文格×动作均值模型，按用户分簇 K 折交叉拟合 | 模型或重权重任一正确即一致；同一用户不跨折，同一条结果不同时拟合和评价 |

主结论取交叉拟合 DR（单步）或轨迹 SNIPW（多步），其余作为稳健性参照。模型在某个
上下文-动作格没有任何已结算观测时返回缺失，**不从近邻用户或相似上下文借值**，该单元
退回纯重权重项，并在 `missing_model_unit_fraction` 中体现。

## 3. 支持度（support）与拒绝规则

离线重权重只在日志策略的支持集内可识别。检查分三层：

1. **硬正性违反**：候选把正概率放在日志概率为零的动作上。单步模式检查候选在该决策
   所有可行动作上的概率；轨迹模式检查每一步。出现即标记 `hard_positivity_violations`，
   直接拒绝，不给出上线结论。
2. **经验外推**：候选在“日志从未实际观测过的上下文-动作格”上投放的概率质量
   （`empirical_gap_mass`）超过 1% 时暂缓。
3. **有效样本量**：ESS `(Σw)²/Σw²`、ESS 占比、最大权重。ESS < 30、占比 < 10% 或
   最大权重 > 50 时不给上线结论。轨迹模式额外报告零权重轨迹占比；确定性候选下部分
   轨迹权重为零是正常的（SNIPW 在支持子集上识别），但**全部**轨迹权重为零即完全无
   支持，拒绝。

## 4. 未结算结果不是零收益

`reward_known_at > cutoff` 的单元是“未结算”，与已观测到的负收益是不同事实：

- 主估计只使用已结算单元，未结算数量与比例单独计数。
- 给出 **Manski 截断界**：把未结算单元按已观测奖励的最小/最大值处理，得到最坏/最好
  边界。边界跨越零时不能确定净收益方向。
- 单步模式另给 **IPCW**（按动作的独立删失假设）作为参照，并显式标注假设；假设不成立
  时该值为 `null` 而不是静默填零。
- 未结算比例超过 20% 或截断界跨零时，建议降级为暂缓。

## 5. 不确定性

- **用户分簇 bootstrap**：以 `user_id` 为簇有放回重采样（同一用户的重复请求不拆开），
  每次重采样在样本内重新交叉拟合模型。净收益差用**配对 bootstrap**（同一次重采样里
  候选估计减基准估计），取 2.5/97.5 百分位，而不是两个独立区间相减。
- 同时给出**簇稳健影响函数标准误**：影响项先按用户聚合，再除以簇数平方根。
- 多步模式额外报告 bootstrap 最大权重分位数，衡量结论对少量极端权重轨迹的敏感性。

## 6. 建议（recommendation）口径

- `proceed_small_traffic`：净收益差的 95% 簇 bootstrap 置信区间整体为正，且全部支持度、
  截断检查通过。这只表示“值得做小流量”，不是直接上线。
- `hold`：区间跨零、未结算不确定、极端权重或经验外推不达标——证据不足。
- `do_not_proceed`：区间整体非正。
- `reject_offline`：硬正性违反或完全无支持，离线数据无法识别该策略价值。

## 7. 口径与版本固化

输出的 `provenance` 固化 `reward_version`、方法版本 `method_version` 和每个候选的
版本指纹（概率表规范化序列化后的 SHA-256 前 16 位）。下一周更换候选文件不会改写
已有结论文件；复查时应另存新分析，并通过指纹确认当时评估的候选内容。

## 8. 本地模拟演示

`tools/run_simulations.py` 用已知生成概率的虚构数据验证三种关键情形，数据写入独立的
空目录，脚本与数据目录隔离：

```bash
python3 -I tools/run_simulations.py --data-dir /tmp/prb-sim-data --output-dir /tmp/prb-sim-out
```

- 演示一：日志策略在易/难上下文上偏好不同动作，只按实际动作分组得到
  “direct 优于 clarify”的错误排序；OPE 恢复出候选相对日志的真实负效应。
- 演示二：候选把 60% 概率放在日志概率恒为零的 `human` 上，触发硬正性违反并被拒绝。
- 演示三：两步 MDP 中扁平化的单步重权重严重有偏，联合似然比 SNIPW 接近真实价值，
  且候选获得正确的正向小流量建议。

任一核验断言失败时脚本以非零状态退出。
